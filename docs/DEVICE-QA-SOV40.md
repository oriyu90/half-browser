## 2. 実機で発見し、修正した不具合

| ID | 症状 | 原因 | 修正 | 検証 |
|---|---|---|---|---|
| B-18 | 設定で証明書を失効しても、同じアプリ内では警告が出ずページが開き続ける | Chromium は許可した証明書例外を **ブラウザプロファイル単位**で保持する。WebView を作り直すだけでは消えない | 失効通知時に、生きた WebView に対して `WebView.clearSslPreferences()` を実行してから再生成 | 失効 → 即座に `/revokecheck` を開き、SSL ダイアログが出ることを実機で確認 |
| B-19 | 読込前のバータイトルが URL 全体になる | `pageTitle` が空のとき `request.url` をそのまま表示していた | フォールバックを `authorityOf(url)`（host:port）に変更。URL 風のページタイトルも除外 | SSL ダイアログ表示中のバーが `192.168.0.165:8844` になることを確認 |
| B-20 | 認証ダイアログをキャンセルすると、サーバーの生 `401 Unauthorized` が表示される | `handler.cancel()` 後に WebView が 401 本文を描画し、`onPageStarted` がエラーペインを消していた | キャンセルした URL を保持し、ページ完了後に AUTH 用のエラーペインを表示（`onReceivedHttpError` でも 401/407 を捕捉） | 「Sign-in required」+ Retry を確認。Retry で認証ダイアログが再表示 |
| B-21 | キーボード表示中にダイアログ外をタップすると、入力中のブックマーク/認証情報が消える | Compose ダイアログの既定 `dismissOnClickOutside=true` | ブックマーク編集・Basic 認証・SSL の各ダイアログで `dismissOnClickOutside=false` | エディタで外側タップ後も入力が保持されることを確認 |

これらはエミュレータ（API 34 / WebView 113）では再現せず、**API 30 / WebView 153 の実機で初めて露出**した。
`WebView.clearSslPreferences()` はインスタンスメソッドであり、失効時の再生成だけでは不十分だった点が特に重要。
