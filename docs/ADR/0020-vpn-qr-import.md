# ADR-0020: VPN プロファイルの QR コード取り込み

- 日付: 2026-11-10（v1.7.0）
- 状態: 採用
- 関連: ADR-0018（アプリ内 WireGuard VPN）

## 文脈

v1.6.0 で設定 → VPN からプロファイルを登録できる（貼り付け / .conf 取り込み）。
公式 WireGuard アプリはプロファイルを QR コードとして表示するため、モバイル間の
移行では QR スキャンが最も速い。スキャン機能を追加する。

## 決定

1. **ライブラリは `com.journeyapps:zxing-android-embedded`（4.3.0）**。zxing core 一式と
   カメラ Activity を同梱し、Google Play 開発者サービスに依存しない（プライバシー、
   de-Googled 端末でも動く）。ML Kit は検出精度こそ上だがバンドルモデルで数 MB 増え、
   thin 版は Play 開発者サービス前提のため不採用。
2. **スキャン結果は「テキスト」として扱い、ファイル取り込みと同じ経路へ流す**。
   デコード文字列 → `VpnConfigParser.parse()` → エディタに事前入力 → ユーザーが確認して
   保存。**スキャン単独で保存・接続はしない**（取り込んだ内容をユーザーが目視確認できる
   ことが信頼境界）。QR の payload 形式は公式アプリと同じ「wg-quick 設定そのもの」。
3. **既存の保証は変更しない**。取り込み元が何であれ、接続時に `VpnScope` が
   `IncludedApplications` を自パッケージへ書き換える（ユーザー設定のスコープ行は除去）。
   サイズ上限は `VpnConfigParser.MAX_BYTES`（QR の最大容量 2,953 バイトより十分大きい）。
   キャンセル（`RESULT_CANCELED`）は無操作。デコード失敗・解析失敗は既存の
   メッセージ経路（インライン / ダイアログ）で表示する。
4. カメラ権限は既存（Web カメラ対応で宣言済み、`required=false`）。新しい権限は追加しない。

## 代替案

- **ML Kit**（不採用）: 精度は高いが APK 増加と Play 開発者サービス依存。
- **スキャン即保存**（不採用）: 誤読・悪意ある QR でプロファイルを即座に登録でき、
  内容確認ができない。エディタでの確認を挟む。
- **CameraX + zxing core 自前実装**（不採用）: プレビュー・権限・解析ループの自前管理は
  不具合面が広い。同梱 Activity の方がクラッシュ安全性が高い。

## 検証

- JVM: `VpnQrRoundTripTest` — zxing で QR 生成 → デコード → パーサ通過の往復、
  非設定テキスト（URL）がパーサに拒否されること。173 件すべて合格。
- エミュレータ（API 36.1）: スキャナ起動、カメラ権限フロー、キャンセルが無操作であること、
  .conf 取り込み（QR と同じ後段経路）→ 保存 → 接続 → `dumpsys connectivity` で
  `Uids: {自 UID のみ}` を実証。日英 UI、FATAL 0。
- エミュレータの仮想シーンへの QR 画像配置は本バージョンでは反映されず
  （`virtualscene-image` コマンドが OK を返すが描画に反映されない）、カメラ → デコードの
  実機 E2E は残課題。デコードの正しさは JVM 往復テストで担保。
