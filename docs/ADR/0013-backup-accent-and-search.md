# ADR-0013: バックアップ/復元・アクセントカラー・検索エンジン・既定ブラウザ UI の削除

- 日付: 2026-11-01
- 状態: 採用（v1.2.0）
- 関連: ADR-0003（認証情報の保存）, ADR-0005（外部 URL / 既定ブラウザ）, ADR-0011（サイト通知）

## 背景

v1.1.0 までで、ブックマーク・設定・証明書ピン・サイト通知・保存済みサインインという
「ユーザーが作ったデータ」が 5 か所に分散した。端末の買い替えや別端末での乗り換え時に
これらを移す手段がなく、すべて手作業で作り直す必要があった。

また、UI のアクセント色が固定で、ダークモードの背景が紺（`#0B1220`）だった。
検索エンジンは Google / DuckDuckGo / Bing の 3 つだけで、既定ブラウザ設定ボタンは
Android のロール画面を開くだけで、実質的な価値が薄かった。

## 決定

### 1. バックアップは 1 ファイルの JSON、パスワードだけ暗号化

- 形式: `format = "halfbrowser.backup"`, `version = 1`。不明フィールドは無視し、
  全フィールドに既定値を持たせて前方互換にする。
- 含めるもの: `settings`（アクセント含む）, `bookmarks`, `siteWatches`, `watchSettings`,
  `trustedSites`, 任意の `credentials`（暗号化 blob）と `credentialCount`。
- サイズ上限 4 MB、ブックマーク 500 / 証明書 100 / 監視 500 件。URL は
  `UrlNormalizer.validateWebUrl` を通らないものを捨て、ID・URL の重複を除去する。
- 読み込みは「統合（既存優先）」と「置き換え（確認チェック必須）」の 2 方式。
  認証情報だけは同一キー（scheme + host + port + realm）で上書きする。
- ファイル入出力は SAF（`CreateDocument` / `OpenDocument`）のみ。ストレージ権限は要求しない。

**なぜパスワードを平文で出さないか**: バックアップはユーザーが任意の場所（クラウド同期
フォルダを含む）に置ける。端末外に出た時点で平文パスワードは漏えい前提になる。
一方で「パスワードも移したい」という要求は正当なので、任意 ON + パスフレーズ必須とした。

**暗号**: PBKDF2-HMAC-SHA256（120,000 回、16 byte salt）→ AES-256-GCM（12 byte IV、
128 bit tag）。GCM のタグ検証がそのまま改ざん検出と「パスフレーズ間違い」の判定になる。
秘密は Keystore に置かない（別端末で復号できなくなるため）。パスフレーズは保存しない。

### 2. アクセントカラーは HSL の 3 軸 + コントラスト自動決定

- 設定は `accentHue`（0–360）, `accentSaturation`（0.15–1.0）, `accentTone`（0–1）の 3 つ。
  既定は 222° / 0.86 / 0.5（従来のブランド青にほぼ一致）。
- 具体的な色は `core/AccentMath.kt` の純粋関数で導出する。primary / primaryContainer /
  secondary / tertiary と、それぞれの `on*` を作る。secondary は +30°、tertiary は −32°。
- `on*` は白か黒のどちらか読みやすい方を選ぶ。白・黒は背景輝度に対して常に 4.58:1 以上の
  コントラストが取れるため、**どの組み合わせでも WCAG AA を下回らない**（単体テストで全 hue
  10° 刻み × 彩度 4 種 × 明るさ 3 種 × ライト/ダークを検証）。
- 壁紙の色（dynamic color）とアクセントは排他。アクセントを動かすと dynamic color を OFF にする。
  そうしないと「スライダーを動かしても色が変わらない」という誤解を生む。
- ダークモードは背景・surface を `#000000`、コンテナを `#0C0C0D`〜`#242426`、文字を
  `#FFFFFF` に固定。dynamic color 使用時もこの surface 上書きは維持する。

### 3. 検索エンジン

- Bing を削除し、Brave / Ecosia / Kagi / Mojeek を追加。テンプレートは各社の `?q=` 形式。
- 保存済み設定が `bing` の場合は DuckDuckGo にフォールバックする（`SearchEngine.fromKey`）。
  設定 JSON に未知のキーが残っていても起動時に落ちない。

### 4. 既定ブラウザ設定ボタンの削除

- Android のブラウザロールは OS 設定でしか選べず、アプリ内ボタンはロール要求画面を開くだけ。
  ホームのカードと設定セクション、`ui/components/DefaultBrowser.kt` を削除した。
- `VIEW`（http/https）の intent-filter は残すため、他アプリの「アプリで開く」候補には出る。

## 影響

- 既存ユーザーのデータはそのまま読める（設定 JSON は追加フィールドのみ、不明キーは無視）。
- 旧 `bing` 設定は DuckDuckGo になる。UI 上の選択肢から Bing は消える。
- バックアップは「別端末の Half-Browser」を前提とする。汎用ブラウザへの移行形式ではない。
- 信頼した証明書もバックアップに含まれるため、読み込むとそのホストの証明書ピンが復元される。
  これは意図した動作（復元後に再確認を強いるほうが不便）だが、信頼の移送であることは
  UI の説明文に明記する。

## 検証

- JVM 単体テスト: `AccentMathTest`（コントラスト全数）, `BackupTest`（往復・拒否・
  サニタイズ・マージ）, `BackupCryptoTest`（往復・誤パスフレーズ・改ざん）, `SearchEngineTest`。
- エミュレータ（API 34）: デバッグ版でエクスポート → リリース版（別パッケージ）へ
  置き換えインポートし、ブックマーク・証明書・監視・サインイン・アクセント・言語が
  復元されることを確認。エクスポートした JSON は Python の `cryptography` で復号し、
  PBKDF2/AES-GCM が標準実装と一致することも確認。
