# ADR-0011: ブックマークサイトのバックグラウンド通知方式

- 状態: Accepted（2026-11-01）
- 関連: PLAN-v1.1 §1.1, §3.2 / ADR-0002（証明書信頼）/ ADR-0003（認証情報）

## Context

「ブックマークしたサイトの通知を管理し、サイトを閉じていても（アプリがバックグラウンドでも）
通知を受け取る」という要件がある。

Android WebView は次を実装していない（実測: エミュレータ WebView 113 / 実機 WebView 153）:

- `window.Notification` → `undefined`
- `PushManager` → 存在しない（`serviceWorker` 自体は true）

したがって、任意のサイトの Web Push / Service Worker 通知を WebView ベースのブラウザで受けることは
できない。サイト側が FCM 等で専用アプリへ送る仕組みも、汎用ブラウザには存在しない。

検討した代替:

| 案 | 内容 | 評価 |
|---|---|---|
| A. サイト更新の定期監視 | WorkManager でブックマーク URL を取得し、内容の変化を検出してローカル通知 | **採用** |
| B. WebView をフォアグラウンドサービスで常駐 | 各サイトを WebView で開き JS の Notification をフック | メモリ・電池・安定性が要件に反する。WebView の通知 API 自体が無い |
| C. Web Push 基盤の実装 | サイト購読 + FCM | 汎用ブラウザでは不可能。サイトごとの対応が必要 |
| D. 実装しない | — | 要件を満たさない |

## Decision

**A（定期監視 + ローカル通知）** を採用する。

- WorkManager の `PeriodicWorkRequest`（最短 15 分、既定 30 分）で、監視 ON のブックマークを
  1 サイトずつ HTTP 取得する。WebView は起動しない。
- HTML を正規化したテキストの SHA-256 と `<title>` を保存し、前回と異なれば通知する。
- 初回はベースライン保存のみ。通知は同一サイト 30 分クールダウン。
- 自己署名 HTTPS は `TrustRepository` の host+port+証明書ピンに一致する場合のみ許可。
  Basic 認証は既存 `CredentialStore`（https のみ）を 1 回だけ試す。
- 通信はタイムアウト 10 秒、最大 512 KiB、リダイレクト 5 回。ネットワーク必須、
  電池残量低下時は実行しない。Wi-Fi のみ設定可。
- アプリ終了後・端末再起動後も WorkManager が実行する。Doze 中は OS が遅延する。

## Consequences

良い点:

- 追加権限は通知（API 33+）のみ。バックグラウンドで WebView を動かさないため省メモリ・省電力。
- アプリを閉じていても通知できる。失敗しても再試行があり、状態を UI に表示できる。
- 既存の証明書信頼・資格情報ストアと一貫したセキュリティモデル。

制約:

- サイト起点の即時通知ではない。更新検出は「取得した HTML の変化」に限られる。
- Cookie セッションや JS レンダリングに依存するページ（チャット等）は検出できない場合がある。
- 最短 15 分。Doze 中は遅延。初回は通知せずベースラインのみ。
- サイト側の Web Push をそのまま受けることはできない。将来必要ならサイト別のネイティブ実装。

## Alternatives considered

- B は「閉じていても」をフォアグラウンドサービスで無理に実現するが、WebView の Notification API が
  無いためサイトの通知を横取りできず、要件を満たせない。
- C は汎用ブラウザの範囲外。ユーザーが管理する任意のブックマークには適用できない。
