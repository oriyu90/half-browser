# v1.6.0 実装計画：アプリ内 WireGuard VPN ＋ JS 攻撃対策

作成日: 2026-11-09 / 対象: Half-Browser 1.6.0（versionCode 9）

## 1. 現状の調査分析（一次情報: コード + 公式ドキュメント + 実測）

### 1.1 VPN 機能の実現可能性

| 事実 | 根拠 |
|---|---|
| 公式 `com.wireguard.android:tunnel` が Maven Central にある（`1.0.20260102`） | Maven Central メタデータ取得 |
| AAR に全 ABI の `libwg-go.so` が含まれる | AAR 内 `jni/` の確認（arm64-v8a 含む） |
| `GoBackend` が `VpnService` を提供し、AAR Manifest がマージされる | 公式リポジトリの `GoBackend.java` / `AndroidManifest.xml` |
| 「このアプリの通信だけ」は `addAllowedApplication` で保証できる | Android 公式 `VpnService.Builder` ドキュメント（AOSP ソースで確認） |
| `getInstalledPackages()` は Android 11+ で可視性フィルタされる | 公式ドキュメント＋ lint `QueryPermissionsNeeded`。除外リスト方式は fail-open |
| WireGuard ライブラリは不明な Interface キーを拒否する | `Interface.parse` のバイトコード確認（未知キーで `BadConfigException`） |
| エミュレータ（API 34, user-net）では protect 済み UDP がトンネル内をループする | 公式 WireGuard アプリでも同一設定で再現（後述 §4） |

### 1.2 JavaScript 攻撃面の現状

| 事実 | 根拠 |
|---|---|
| JS ダイアログは WebView 標準に任せていた（`onJsAlert` 等なし） | `HalfBrowserWebViewClient` に未実装 |
| `window.open` は `onCreateWindow=false` で既に拒否 | `HalfBrowserChromeClient.onCreateWindow` |
| `javascript:` 等の scheme は `shouldOverrideUrlLoading` で拒否 | `handleSystemScheme`（tel/mailto/sms/geo のみ許可） |
| `beforeunload` の扱いなし | 未実装 |
| 既存の document-start 注入機構あり | `installDocumentScripts`（WebCompat / KeyboardGuard / WebNotify） |

## 2. 実装案の比較（VPN スコープ）

### 案A: 除外リスト（他アプリを全部 `addDisallowedApplication`）
- **却下**。Android 11+ のパッケージ可視性で列挙漏れが出る。漏れたアプリがトンネル内に入る
  fail-open になり、「このアプリの通信だけ」という要件を保証できない。

### 案B: 許可リスト（自パッケージだけ `addAllowedApplication`）— 採用
- 自分の名前だけを必要とし、列挙漏れなし。後から入ったアプリも外側に残る fail-closed。
- WebView レンダラは自 UID のためカバーされる。
- ライブラリ版が将来 `IncludedApplications` を落とす場合に備え、解析結果を自己検証する
  除外リストへのフォールバックを備える。どちらも不可なら接続失敗として扱う
 （「全アプリがトンネル内」では起動しない）。

## 3. 実装内容（v1.6.0）

### VPN（ADR-0018）
- `core/VpnConfig.kt`: 厳格パーサ（鍵の canonical base64、Endpoint/CIDR/数値範囲、上限付き）。
- `core/VpnScope.kt`: allow-list 書き換え（ユーザー指定スコープ除去、冪等）。
- `data/VpnStore.kt`: Keystore 暗号化保存（平文保存なし、Keystore 不可時はメモリ専用）。
- `data/VpnController.kt`: `GoBackend` ライフサイクル（IO スレッド、状態フロー、再接続の競合回避）。
- 設定→VPN タブ: 追加／編集／削除／ファイル読み込み／書き出し／選択／自動接続。
- ホーム下部パネル（`bottomBar`）: 状態ドット＋接続／切断／再接続、登録一覧（折りたたみ）、管理への導線。
- バックアップには含めない（秘密鍵をファイルに出さない）。書き出しは明示操作時のみ。

### JS 攻撃対策（ADR-0019）
- `core/JsGuard.kt`: document-start シム（ダイアログ制限・ポップアップ・beforeunload・
  `javascript:` 遷移）＋ `DialogBudget`（ネイティブ側の同ポリシー）。
- `HalfBrowserChromeClient`: `onJsAlert/Confirm/Prompt/BeforeUnload` のアプリ側ダイアログ化
  （origin 表示・テキスト sanitize・予算）。
- 設定→セキュリティにトグル（既定 ON）。

### 品質
- 日英 424/424 キー一致（`LocaleParityTest`）。
- JVM テスト 162 件 / 失敗 0、lint 0 errors。
- 既存の互換性（バックアップ形式、設定 JSON、証明書ピン、資格情報ストア）は変更なし。
  設定への追加フィールドは既定値付きで後方互換。

## 4. エミュレータ検証結果（2026-11-09, API 34 / WebView 113）

- VPN: インポート→保存→同意→接続でトンネル Up（`Device started`）、VPN ネットワークに
  自 UID のみ紐付け。再接続の競合（即時切断）も修正・再確認済み。
- **ハンドシェイクのパケット到達は未確認**。このエミュレータ（user-net）では protect 済み
  UDP がトンネル内をループし、ホストの対向サーバに届かない。公式 WireGuard アプリでも
  同一設定で再現したため、エミュレータ環境の制限と判断。実機確認は残課題。
- JS 攻撃: alert 連打 20 → 12 表示・8 ブロック、popup 5 → 5 ブロック、
  beforeunload 5 登録 → 3 ブロック（離脱可能）、`javascript:` 代入は実行されるが
  その alert は予算でブロック。
- UI: 日本語・英語とも VPN タブ／ホームパネル／セキュリティを目視確認。

## 5. 未対応・残課題

- 実機での WireGuard 対向接続確認（エミュレータ制限のため）。
- クロスサイト遷移の確認ダイアログ（ユーザー操作の有無を確実に得られない）。
- macOS 版への VPN / JS ガード移植（別途検討）。
