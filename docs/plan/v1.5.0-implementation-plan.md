### Web Notifications についての技術的事実（SDK スタブで確認）

- `android.webkit.PermissionRequest.RESOURCE_*` は `AUDIO_CAPTURE` / `VIDEO_CAPTURE` / `MIDI_SYSEX` / `PROTECTED_MEDIA_ID` の 4 つのみ。**通知リソースは存在しない**。
- したがって WebView ネイティブの通知許可フローは無く、Chromium の通知 API も WebView では公開されない。
- Chrome が即時配信できるのは Google Play Services の push 経由。WebView アプリは同等の経路を持たない。

→ 方針: **`Notification` を document-start で JS ポリフィルし、`WebMessageListener` 経由で Android 通知に変換する**。ページが生きている間（アプリがバックグラウンドでもプロセスが生存している間）は即時配信。さらにフォアグラウンドサービスでプロセスを維持するオプションを用意する。プロセスが死んだ後の push は不可能であることを UI に明記する。

## 1. 作業項目と設計

### P1 UIスケールを Web ページへ反映

- `WebZoom` ユーティリティを新設し、`uiScale` を WebView のページズームとして適用する。
- 第1候補: `WebView.setInitialScale((100 * uiScale).roundToInt())`。viewport meta がある場合の実挙動をエミュレータで実測し、効かなければ次候補へ。
- 第2候補: WebView へ渡す `Context` の `DisplayMetrics.density` を差し替える（CSS px の実寸を変える＝ページズーム相当）。
- 第3候補: `textZoom` に `uiScale * fontScale` を掛ける（テキストのみ）。
- `100vh` / `position:fixed` を壊す CSS 注入は**行わない**（v1.4.0 の回帰の再発防止）。
- 検証: 専用テストページ（200px の赤枠 + `innerWidth` / `devicePixelRatio` 表示）で、1.0 と 1.4 の描画幅をスクリーンショットのピクセル計測で比較。

### P2/P3 ブックマーク起動時の上部バー

- `request.bookmarkId != null` のとき「コンパクトモード」:
  - 高さ 56dp → 44dp、1 行。
  - 左: 🏠（`Icons.Filled.Home`, ホームへ）+ 🔄（再読み込み）。
  - 中央: `タイトル · ドメイン` を 1 行（`·` 区切り、タイトルは ellipsis）。
  - 右: ☰（ブックマーク切替）+ ⋮。
- ブックマーク以外（外部リンク等）は現行の 2 段バーを維持。

### P4 Shift+Enter

- 監査結果に従い、アプリ側で修飾キーを落としている箇所を修正。無ければ「WebView へ素通しされている」ことを確認し、必要な場合のみ `dispatchKeyEvent` で補正する（IME が Enter を消費する経路への対処）。

### P5 通知の即時配信

- `notifications/WebNotificationBridge.kt`: `WebViewCompat.addWebMessageListener("HalfBrowserNotify", setOf("*"))` で受信。`sourceOrigin` を検証し、`SitePermissions` の通知許可があるオリジンのみ受理。
- `core/WebNotify.kt`: ポリフィル JS（`window.Notification` の class、`permission` getter、`requestPermission()`、`new Notification()`）。
- 許可要求はアプリ内ダイアログ（サイト単位・記憶する）。
- `service/KeepAliveService.kt`: 「バックグラウンド通知」有効時のみフォアグラウンドサービス（`dataSync`）でプロセスを維持し、`pauseTimers()` を抑止。
- 制約の明示: プロセス終了後の push は不可。Chrome の同等機能は Google の push 基盤依存。

### P6 サイト権限の一括管理 + 設定タブ化

- `core/SitePermissions.kt` + `data/SitePermissionRepository.kt`: `origin -> {notifications, camera, microphone, location, jsPopups}` を JSON 永続化。既定は「都度確認」。
- `onPermissionRequest` / 位置情報 / 通知ポリフィルはこのストアを参照（許可済みなら無ダイアログ、拒否済みなら即拒否、未決定ならダイアログ）。
- 設定画面をタブ化: **表示 / 閲覧 / サイト権限 / 通知 / セキュリティ / バックアップ / アプリ情報**。
- サイト権限タブ: サイト一覧（オリジン + 各権限の現在値）→ タップで変更、全消去。

### P7 ブックマーク切替（☰）

- バー左の ☰ で `ModalBottomSheet` を開き、ブックマークをアイコン付きで一覧。タップで `container.requestOpen(url, id)`。

## 3. リスク

- `setInitialScale` が効かない端末がある → 実測で代替へ切替。
- JS ポリフィルがページ側の `Notification` 利用コードと衝突 → `Notification` 未定義時のみ定義し、`permission` は getter で返す。
- フォアグラウンドサービスは常駐通知が増える → 既定 OFF、明示的に有効化したときだけ。
